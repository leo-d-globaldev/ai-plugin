# GDV AI-KIT

Claude plugin for GlobalDev's AI-native software lifecycle, built on Anthropic's **AI-native SDLC playbook** (https://academy.claude.com/courses/ai-native-sdlc-playbook/introduction). The repo is the axis of the work: each change has a folder `intent/<ID>/` with `intent.md → spec.md → plan.md → tests.md`, next to the code. The stages are modular: a project uses the ones it needs. People stay accountable for every judgment; hooks enforce the gates.

**Workflow overview (interactive HTML):** [https://claude.ai/artifact/4GBYPhAQbU6EPcZESM1fMa](https://claude.ai/artifact/4GBYPhAQbU6EPcZESM1fMa). Source: `docs/ai-kit-workflow-v1.html`. On every plugin publish, replace the content of the same artifact URL, never create a new one.

**Slides (intro deck, Vietnamese):** [https://claude.ai/artifact/ApfZUinifu2XskcBP82KNq](https://claude.ai/artifact/ApfZUinifu2XskcBP82KNq). Source: `docs/ai-kit-slides.html`. Same rule: replace the content of the same artifact URL on every publish.

## Install

- From the GlobalDev organization's plugin library on claude.ai (enabled for everyone through managed settings, `docs/platform.md`).
- For a local test of a clone: `claude --plugin-dir PATH_TO_CLONE`.

Source repo: internal.

## Getting started

1. In the project repo run `/ship-init` once: it sets up `CLAUDE.md` (with the `## AI-KIT` section), `REVIEW.md`, the intent home (a folder, a sparse checkout, or a separate docs repo for large monorepos and multi-repo projects), the data class, the tracker (`jira`, `windshift` or none) and your role.
2. Then just say what you want. The right skill loads from your words ("làm ticket PROJ-123", "review trước khi commit", "QC cần làm gì"); a SessionStart hook tells Claude the repo's setup and the open work. Prefer one command? `/ship <what you want>`.
3. Something wrong: `/ship-doctor`.

## Stages and skills

| Stage (playbook) | Skill | Who | Output |
|---|---|---|---|
| 1 Plan — Capture as intent.md | `/ship-intent` | PO, BA, PM | `intent.md`, approved by the PO/BA |
| 2 Design — Requirements and design in one session | `/ship-spec` | BA, PO (lead for design) | `spec.md`: requirements, Given/When/Then acceptance, design per repo, contracts between systems, flagged concerns; child intents (`parent`, `owner`, `depends-on`) when several people build it |
| 3 Build — Plan mode, CLAUDE.md, skills, parallel sessions | `/ship-build` | Dev (approves own plan; lead reviews the MR/PR) | `plan.md`, code with a feedback loop, verifier verdict |
| 4 Test — Feedback loop, evals | `/ship-test` | QC | `tests.md`, e2e tests, runs, bugs with a failing test |
| 5 Deploy — AI review, hooks as gates | `/ship-review` + `hooks/gates.py` | Dev, lead | review of HEAD; push and PR/MR blocked without it |
| 6 Maintain — Closing the loop | `/ship-maintain`, `scripts/control-band.py` | on-call, PO | draft `intent.md` from a signal, for triage |
| Any | `/ship`, `/ship-init`, `/ship-doctor`, `policy-client-data` | everyone | routing, setup, health check, customer-data policy |

Shared rules for every skill (config, intent folder, statuses, approvals, work log, gates): `CONVENTIONS.md`. Usage flows per kind of project (project-based, staff-aug/ODC, maintenance, ongoing Jira projects, several tickets at once, one change across several systems and people, QC): `docs/ai-kit-workflow-v1.html`.

## Hooks

`hooks/hooks.json` registers three Python scripts (need `python3`, no packages). They act only in a repo whose `CLAUDE.md` has a `## AI-KIT` section.

- `gates.py` (PreToolUse): push or PR/MR creation of a commit with no AI review (`review-gate: block|ask|off`; pushes of intent and `.ai/` files only are exempt), push to the main branch, force push, branch deletion, production deploy commands, edits of protected paths (migrations, infra, CI), test edits under a bug-fix lock, tracker deletes and closing a ticket. Project additions: `.claude/gdv-gates.json` (format in the script header).
- `context.py` (SessionStart): the repo's AI-KIT config, your role and the open intents, so plain words pick the right skill.
- `work-log-hook.py`: reminds (or, with `worklog: strict`, requires) a work log per change; records end in `.ai/worklog/` and are committed.

Optional git pre-push hook for pushes outside Claude: `scripts/pre-push.sh` (`/ship-init` offers it).

## Verifier agent

`agents/gdv-verifier.md`: `/ship-build` starts it in a fresh session with only the criteria, the diff and the verify commands; it reports PASS, FAIL or BLOCKED with the command output and changes nothing.

## Tracker

Two operations only, used when needed: `get-item` (read a ticket to seed an intent) and `add-comment` (only when asked or `tracker-comments: on`). Adapters: `adapters/jira/`, `adapters/windshift/`. Contract: `adapters/OPERATIONS.md`.

## Measuring

- Work log: one JSON file per skill run in `.ai/worklog/YYYY-MM/` (time, tokens, outcome, role, models and effort levels with tokens per pair; no names), committed with the work (`scripts/work-log.py`).
- `scripts/metrics.py`: lead time (intent to merge), first-pass review rate, rework rate, AI cost per skill, role, model and effort, from git and the work log. Measure a baseline before the pilot.
- OpenTelemetry per project: managed settings turn it on and name the collector; `/ship-init` tags the project (`project`, `data_class` in `OTEL_RESOURCE_ATTRIBUTES`), `/ship-doctor` checks it. See `docs/platform.md`.

## Platform

`docs/platform.md`: data classes A/B/C per customer contract, managed settings (`templates/managed-settings.json`), sandbox, managed MCP, OpenTelemetry, the local review gate and its limits, the scheduled Maintain loop. `docs/client-ai-statement.md`: the one-page answer for customers (draft, needs legal review).

## Evals

`evals/`: offline hook evals (`evals/run.py --kind hook`), work-log evals (`--kind worklog`) and task evals (`claude -p` with the plugin; paid). How to add one, including one per production bug: `evals/README.md`. Maintainers: `bash evals/install-hook.sh` once per clone installs the pre-push hook that runs them.

## Migration from 0.x

1.0.0 removes the tracker-driven lifecycle. Removed skills and their replacement:

| 0.x | 1.0.0 |
|---|---|
| `/ship-ba-epic`, `/ship-pm-feedback` | `/ship-intent`, `/ship-maintain` |
| `/ship-lead-design`, `/ship-ba-epic-breakdown` | `/ship-spec` (no breakdown: one intent per change) |
| `/ship-dev-execute` | `/ship-build` |
| `/ship-lead-ai-review` | `/ship-review` (local, gated by the hook) |
| `/ship-qc-testcases`, `/ship-qc-triage` | `/ship-test --plan`, `--run`, `--bug` |
| `/ship-next`, `/ship-*-next` | automatic skill choice, `/ship` |
| `/ship-pm-plan`, `-effort`, `-status`, `-risk`, `-retro`, `-release`, `-client-report`, `/ship-dev-deploy` | removed (playbook: no sprint planning layer); numbers from `scripts/metrics.py` |

In a project: run `/ship-init` again (it replaces `## AI-DLC defaults` with `## AI-KIT`), then `/ship-doctor`. Tickets and pages already on Windshift stay there; new work starts in `intent/`.
